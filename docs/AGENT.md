# 자동 작업 에이전트 규칙

매시간 예약 작업이 실행되어 Claude가 이 문서를 따라 플랫폼을 계속 개선한다.
사용자(제작자 윤용현 선생님)는 컴퓨터를 켜 두지 않아도 되고, 결정이 필요한 일만 알림으로 받는다.

## 한 번 실행할 때의 순서
1. `git pull` → `CLAUDE.md`, `docs/DECISIONS.md`, `docs/ROADMAP.md`의 "에이전트 작업 목록"을 읽는다.
2. `docs/DECISIONS.md`에서 사용자가 답한 항목을 반영한다(답한 항목은 "결정됨"으로 옮긴다).
3. 작업 목록에서 **결정 없이 할 수 있는** 가장 위 항목 1~2개를 고른다. 결정을 기다리는 항목은 건너뛴다.
4. 작업 → `npm run validate && npm run build` → 에뮬레이터에서 `node scripts/e2e.cjs` → 화면이 바뀌었으면 스크린샷으로 직접 확인.
5. **모두 통과하면** `main`에 커밋·push(자동 배포). 하나라도 실패하면 고치거나, 못 고치면 되돌리고 push하지 않는다.
6. 배포 성공을 확인(GitHub Actions 결과, 실제 사이트)한 뒤 `docs/ROADMAP.md`를 갱신한다.
7. `docs/AGENT-LOG.md` 맨 아래에 한 줄 기록하고 push한다(변경이 없어도 기록은 하지 않는다).
8. 알림을 보낸다(아래 기준).

## 매일 숫자 점검
- 매일 새벽 배포 때 `npm run check:stats`가 홈·메뉴 숫자(`src/data/stats.ts`)를 실제 데이터·졸업 학점 규칙·나이스 공식 학교 수와 대조한다. 숫자가 틀리면 배포를 멈춘다(오류), 나이스와 학교 수가 다르면 경고만 남긴다.
- 그날 첫 실행에서 최근 배포 실행의 점검 결과(경고·오류 주석)를 확인하고, 문제가 있으면 고친 뒤 `docs/AGENT-LOG.md`에 "숫자 점검"으로 기록한다(알림 담당이 휴대폰으로 알림).
  - 주석 확인: `curl -s https://api.github.com/repos/nagusdl87-create/-/check-runs/<job id>/annotations`

## 사용자에게 먼저 물어야 하는 것 (자동으로 하지 않음)
- 디자인 전면 수정, 메뉴 구조 변경, 기존 기능 삭제
- 새 외부 서비스·로그인·개인정보 수집, 비용이 생길 수 있는 일
- 교육청·학교 등 기관 자료를 쓰는 데 동의가 필요한 일, 사실 확인이 어려운 내용 게시
- 제작자 표기·저작권·비공식 고지 관련 변경 (원칙상 변경 금지)

물을 때는 `docs/DECISIONS.md`의 "대기 중"에 항목을 추가하고(번호, 질문, 선택지, 추천안), 알림으로 알린다.
답을 기다리는 동안에는 그 항목만 멈추고 다른 작업을 계속한다.

## 알림 기준
휴대폰 알림은 별도의 "알림 담당" 예약 작업(2시간마다, 08~22시)이 `docs/AGENT-LOG.md`·`docs/DECISIONS.md`를 읽어 보낸다. 그래서 기록과 결정 항목을 빠짐없이 적는 것이 알림의 전부다. 작업 세션에서도 PushNotification을 함께 시도한다.

- 보냄: 결정 요청, 배포 완료(무엇이 바뀌었는지 한 줄), 실패해서 사람이 봐야 할 때
- 보내지 않음: 바뀐 것이 없는 실행
- 형식: 200자 이내, 첫머리에 할 일. 예) "결정 필요 D3: 다크 모드 기본값 — 대화창에서 답해 주세요" / "배포 완료: 오프라인 사용 지원 추가"

## 안전 장치
- 키·비밀번호를 저장소나 대화에 쓰지 않는다. GitHub Secrets만 쓴다.
- 커밋 메시지·문서에 모델 이름을 넣지 않는다.
- 한 번에 큰 변경을 몰아서 하지 않는다. 되돌리기 쉬운 단위로 커밋한다.
- 작업 목록이 비면 새 아이디어를 "대기 중" 결정 항목으로 제안하고 기다린다.
